The PlatformConsole deserves a slightly different treatment from Web.React. It is an administrative console, so the sidebar should prioritize compactness, predictable navigation, tenant/security task access, and a clear administrative identity rather than displaying sports-performance navigation categories.

From the current `Layout.tsx`, the console already has several good foundations: grouped navigation, active-route styling, a scrollable navigation area, a fixed sidebar, and a compact email/sign-out footer. The improvements should build on those foundations.

## 1. PlatformConsole-specific defects and solutions

| Issue in current implementation                                            | Recommended solution                                                                      |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Fixed 240px sidebar with no compact mode                                   | Keep 240px expanded; optionally add a 64–72px icon rail                                   |
| Section labels use very small 10px uppercase text                          | Use readable 11–12px section labels with consistent spacing                               |
| Active item uses a green tint and left border, but can be more distinctive | Use a subtle green surface, stronger text, and a 2–3px accent indicator                   |
| Brand badge and brand header occupy separate vertical areas                | Combine them into a more compact brand block without losing the Platform Console identity |
| Footer only shows email and sign-out                                       | Use a compact account area; retain the email and sign-out action                          |
| Collapsible groups have no explicit accessibility state                    | Add `aria-expanded`, stable IDs, and keyboard-visible focus styles                        |
| Main content is offset by a hard-coded `pl-[240px]`                        | Derive sidebar and content offsets from the same expanded/collapsed state                 |
| Header has theme and language controls but no responsive strategy          | Preserve these controls and prevent them from overflowing at narrower widths              |

Unlike Web.React, PlatformConsole should not have the sports-performance app's larger athlete-navigation groups or a demo system-health card unless the console has an actual operational requirement for one.

## 3. Implementation recommendations

### A. Navigation hierarchy

Keep the current route structure and labels, but use these visual groupings:

- Overview — Dashboard
- Tenants & Users — Organizations, Users
- Catalogs — Protocols, Metrics, Devices, Algorithms
- Security & Audit — Audit logs

The group headings can be slightly more descriptive than the current short labels if that helps first-time administrators. Ensure the translation keys are updated for both English and Chinese.

### B. Active navigation state

Use a consistent state design:

- Default: neutral sidebar text.
- Hover: subtle background change.
- Active: light green-tinted surface, readable accent text, and a narrow left indicator.
- Focus: visible keyboard ring.
- Disabled, if used: reduced emphasis and a clear disabled state.

The active state should not depend on color alone. Keep the current `isActive()` logic for exact routes and nested routes, including organization details.

### C. Collapsible sidebar

A compact mode is useful for a console where administrators may need wider tables. However, make it optional and preserve the current expanded layout as the default.

When collapsed:

- Show only icons, with tooltips and accessible labels.
- Hide group labels and text without hiding any destinations.
- Keep the current route visibly selected.
- Ensure the content area's left offset updates with the sidebar width.
- Preserve the user's preference during navigation; persist it only if the product needs that behavior.

### D. Fix group collapse behavior

In the current implementation, a group can remain collapsed when a route inside it becomes active. Add logic to ensure the active route's group is expanded. Do not automatically expand every group or erase the user's other collapse choices.

Also add `aria-expanded` to the group toggle buttons, and ensure focus remains visible when navigating using the keyboard.

### E. Footer and header

The footer currently contains the administrator email and sign-out button. Keep both, but reduce unnecessary padding and align them with the sidebar's overall spacing. Consider using an avatar or account icon to help distinguish the account area.

In the header, keep the breadcrumb/title, theme selector, language switcher, and admin-role indicator. At narrower widths, make the title truncate gracefully and allow controls to adapt without horizontal overflow.
