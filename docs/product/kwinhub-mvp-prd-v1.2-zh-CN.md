## 1. 产品背景与定位

### 1.1 需要解决的问题

1. 各客户端分别维护人员和测试数据，跨产品归档、历史比较和报告汇总成本高。
2. 1.0 的扩展限制需要被具体识别；不能只以“老系统不够用”作为重建理由。
3. 用户最终需要可解释的测试结果和专业报告，单纯上传成功或展示孤立图表不足以完成业务。
4. 不同机构、角色及敏感数据的访问边界必须明确，避免统一平台造成数据混用。
5. 新客户端接入、老数据迁移与国内外部署需要有演进路径，降低再次重建的风险。

以上为问题归纳；1.0 具体缺陷、影响客户和复现证据须由产品与研发补齐，不能据本文推断代码存在某项缺陷。

### 1.2 一句话定位

**KWinHub 是坤维统一的运动表现数据与报告平台，连接现有采集 App、人员档案、测试结果和测试方案，为机构与专业人员提供安全归档、基础比较和报告输出能力。**

长期支持政府/科研、机构和个人等场景，复用统一底座；一期优先完成国内版本、iOS 2.0 接入及展会/试点闭环，不同时建设三套完整业务门户。

### 1.3 产品职责边界

| 对象 | 一期职责 |
|---|---|
| 现有 App | 设备连接、采集、校准、本地操作与离线保存；按现有已验证算法输出指标及 App 报告；测试数据与视频分队列同步 |
| KWinHub | 账号与机构访问边界、标准身份、接入校验、文件归档、基础统计、历史比较、在线方案报告、视频授权、媒体状态及任务协调、审计与运维 |
| KWinScience | 现有科学能力保持复用方向；一期不以迁入 Hub 或云端重算为依赖 |
| 后续扩展 | 更多 App/硬件、跨产品完整方案、第三方开放接口、海外部署、可选科学计算服务；另行评审 |

Hub 可以按明确口径进行平均值、最大值等统计；不得把“统计”扩展为从原始力信号重新计算跳高、事件检测、动作识别或 AI 建议。新派生科学指标必须独立评审。视频转码、封面生成、播放分发属于媒体处理，不等于云端运动指标科学重算。

### 2.2 成功标准

- 试点角色能在标准界面完成核心流程，无需手工修改数据库。
- 网络中断恢复后可重试；逻辑测试记录不因重试而重复。
- 人员、指标、附件与报告均可追溯至来源与版本。
- 所有跨机构及无权限访问验收用例通过，包括文件与导出路径。
- 选定展会方案在同一产品内运行，不另建一次性演示应用。
- 试点前完成备份恢复验证；容量、响应时间等数字按 §10 冻结。
- 指标成功接收后可查看；视频上传、转码失败不伪装成会话丢失或视频可播放。
- 视频权限校验、消息重投、Worker 崩溃、回调丢失及媒体删除等新增验收通过。

## 3. 用户与权限

### 3.1 一期主要用户

| 角色 | 核心任务 | 默认限制 |
|---|---|---|
| 机构管理员 | 管理本机构成员、角色、人员及分组，处理受控身份关联 | 无其他机构权限；敏感导出另行授权 |
| 教练/体能师 | 查看授权人员、历史与比较，生成报告 | 仅授权人员或分组；不能管理机构成员 |
| 测试操作员 | 选择/建立授权人员，在 App 测试并确认同步 | 仅工作范围内采集与上传，默认无全量导出 |
| 科研人员 | 读取授权数据、按许可导出脱敏结果 | 科研身份不自动获得全库或原始敏感数据 |
| 平台运维管理员 | 维护租户与运行状态，排查授权问题 | 默认无业务数据内容访问权；临时访问需授权并审计 |

个人账号与运动员档案是不同概念：有档案不等于必须拥有登录账号。独立个人门户、政府监管门户及官网统一登录的完整实现，列为待定/后续范围，不默认成为一期三套前端。

### 3.2 权限规则（产品补充，评审后冻结）

1. 权限取决于当前机构成员关系、角色、人员/分组范围和操作类型；服务端每次校验。
2. 读取、编辑、下载原始文件、查看敏感字段、导出、授权及删除分别控制。
3. 同一用户可加入多个机构，但切换机构后只显示当前机构上下文；机构数据不自动共享。
4. 多分组授权按已授予范围合并；显式禁止与敏感数据限制优先，具体规则须写入权限矩阵。
5. 角色变更、成员停用或授权撤回后，后续请求应按新权限执行；现有访问凭证的失效时间须在安全评审中确定。
6. 姓名、手机号不作为唯一身份或权限依据；客户端传入的机构 ID 不能替代授权校验。

### 4.1 一期不做

- 新建独立 iOS/Android 消费者 App，或重写所有现有客户端。
- Hub 原始信号科学计算、算法迁移、云端权威结果切换、历史科学重算。
- AI 训练建议、医疗诊断、损伤预测及复杂动作识别。
- 完整训练计划/处方、教务、会员计费系统。
- 大型 BI 大屏、任意自定义图表/报表设计器、常模数据市场。
- 大规模第三方硬件适配、视频信号同步编辑工作台；多机位同步回放、逐帧分析及标注不在普通在线播放承诺内。
- 为采用 SaaS 而强制全面微服务化、全局强分布式事务或 Kubernetes；组件引入必须有业务及运维依据。
- 跨机构默认汇总、跨境数据传输、海外多区域生产部署。

基础模型支持多个设备/数据源，不代表上述产品都要在一期接入。冷热分离是长期存储方向；一期先完成业务数据库与文件存储分离，是否实施额外冷存储服务由容量评估确定。

## 5. 核心工作流与页面

### 5.1 工作流

**A：建档与身份确认。** 登录并确认机构 → 查询人员 → 选用已有档案或新建 → 分组 → App 取得/缓存 Hub 身份映射。离线建档使用稳定临时 ID；同步时有冲突需人工确认，不能按姓名自动合并。

**B：采集与接入。** App 采集并完成指标计算、本地持久化 → API 独立提交会话、试次、指标及文件清单 → 服务端幂等接收并返回 Hub ID/资产引用，指标即可以读取。App 再逐资产申请短时授权，直接上传原始文件、App 报告及视频；服务端确认对象完整性后推进媒体任务。两条链路分别记录状态与重试，不要求视频完成后才能接受下一次测试。

**C：查阅与比较。** 选择人员/分组 → 筛选测试与日期 → 查看来源、试次、指标、附件 → 选择可比较指标 → 展示基础统计与图表。单位、定义或条件不兼容时说明原因。

**D：方案与报告。** 选择已发布方案版本 → 选择人员及测试时间范围 → 系统列出候选记录 → 用户确认入选会话/试次规则 → 检查缺失项 → 预览 → 生成并导出报告。不能将其他人员或机构的数据补入方案。

**D2：报告内视频播放。** 用户打开在线报告 → API 校验机构、人员与报告权限 → 返回指标及各视频状态 → 对 Ready 视频再次检查资源权限并取得短时播放凭证 → 播放器通过媒体分发服务取流。非 Ready 视频显示待上传/处理中/失败，不阻断有效指标查看。

**E：迁移与切换。** 盘点老库及客户端 → 规则映射与冲突清单 → 试迁移 → 核对 → 批次执行与最终增量 → 协同发布客户端 → 验证新写入去向 → 监控与回退。未到正式切换节点不得默认关闭旧链路。

### 5.2 页面与最低交互要求

| 页面 | 必需内容 |
|---|---|
| 登录/机构选择 | 当前账号、可访问机构、明确的失效/无权限反馈 |
| 人员列表/详情 | 查询、分组、稳定编号、历史测试、档案归档状态 |
| 测试记录/详情 | 日期、协议、来源、设备、试次、指标、附件与同步状态 |
| 方案/报告 | 可用模板、数据选择、在线报告、逐视频状态与授权播放器、缺项提示、导出 |
| 同步记录 | 会话、逐文件上传及媒体处理的独立状态、失败项、重试入口与关联编号 |
| 机构设置 | 成员、角色、授权范围；敏感操作二次确认 |
| 运维/审计 | 限授权人员查看的事件检索、失败任务与运行信息 |

主导航优先使用“人员、测试、方案与报告”等业务名称；数据库实体、算法任务与基础设施名词不作为普通用户主流程。空状态、加载、失败、无权限和部分完成均需明确设计。

## 6. 功能需求与验收标准

### FR-01 账号、机构与成员（P0；继承＋补充）

- 支持登录、退出、会话过期处理，展示当前机构与角色。
- 成员只能访问已授权机构；成员停用不能继续提交或读取该机构业务数据。
- 账号认证与运动员身份分离；认证实现沿用经技术评审的现有方案，不另造密码体系。
- **验收：** 用户有 A/B 两机构成员关系时可切换，数据随上下文变化；无 B 成员关系时直接请求 B 资源被拒绝。

### FR-02 角色与资源授权（P0；会议方向＋补充）

- 采用预置角色，配置机构内人员/分组可见范围；完整角色与操作矩阵是开发输入。
- 会话、试次、结果、报告、文件、视频媒资、播放凭证和导出任务都必须存在可验证的租户授权路径。客户端或消息传入的机构/媒资 ID 不能替代服务端归属检查。
- 原始文件与敏感资料默认不因“可看指标”而一并开放。
- **验收：** 列表、详情、写入、对象下载和后台导出均测试横向越权与角色越权；无权限响应不得泄漏人员信息或文件内容。

### FR-03 人员档案与跨 App 身份（P0；会议方向＋补充）

- 每个机构管理独立人员档案；Hub ID 可技术上全局唯一，但不代表可跨机构识别人或共享档案。
- 维护 `机构＋来源应用＋来源安装/数据库标识＋外部人员 ID → Hub 人员 ID` 的显式映射；来源范围按真实客户端确认。
- 允许同名、同手机号、无手机号；不收集完成业务不必要的身份信息。
- 来源身份冲突进入待处理清单，未确认前不能自动用于综合报告。
- 一期至少提供管理员确认来源关联的受控流程；批量合并工具可后置，但不得直接改库完成日常关联。
- 档案归档不删除历史测试；删除走 FR-12。
- **验收：** 同名不同人不被合并；同机构同一人来自不同 App 时可经审核关联；相同外部 ID 在不同来源/机构不串档；修改姓名不破坏历史。

### FR-04 基础队伍与分组（P0；继承 V1.1）

- 创建、编辑、归档分组，维护人员成员关系，支持列表和测试筛选。
- 分组归档或成员变更不改写测试事实；权限变化按当前授权规则执行。
- 一期不建设复杂项目树、训练周期或赛事组织系统。
- **验收：** 人员移组后历史记录仍可追溯；用户不能通过另一分组访问未授权人员。

### FR-05 测试协议与组合方案（P0；会议方向＋产品补充）

- `TestProtocol` 表示单项测试定义及版本，如具体 App 的某类测试；`AssessmentPlan` 表示一个或多个测试/指标的组合方案，避免将两者混用。
- 方案至少定义名称、版本、适用测试、必需/可选指标、指标顺序、单位、入选规则和报告模板版本。
- 一期采用受控模板配置：由授权管理员维护，至少发布一套展会方案；不要求通用可视化设计器。
- 已被报告引用的方案版本不能原地改写；修改生成新版本。
- 每个方案项指定取值规则：选定试次、最佳试次、均值或最近一次等；禁止默认混用。
- 同名指标不能只按显示名匹配；以代码、定义版本及单位进行匹配。
- **验收：** 发布方案可生成报告；调整方案不改变旧报告；缺项、身份不确定或版本不兼容有明确反馈。
- **边界：** 一期实际数据来源为 iOS 2.0；未来多产品组合通过模型评审验证，不能展示成已实现的真实多端接入。

### FR-06 iOS 2.0 接入契约（P0；会议明确＋继承）

- 明确首个 App 的正式产品名、版本、对接负责人和支持测试清单。
- 提交人员映射、协议、会话、试次、指标值与单位、来源版本、设备信息、测试时间及文件清单；会话、文件上传、完成确认和播放授权分别定义契约。
- App 完成科学指标计算；Hub 检查结构、类型、单位与关联完整性，不重算原始信号。
- 保存可提供的计算版本、配置/方法信息；旧数据缺失时标注未知，不补造科学溯源。
- Schema 与接口版本化；不支持的版本返回稳定错误码及修复说明。
- **验收：** 使用双方确认的真实脱敏 payload 上传；Hub 展示值与 App 提交值一致（显示精度除外）；无云端科学计算也可完成全流程。

### FR-07 可靠同步与独立状态（P0；继承＋用户确认＋产品补充）

- App 持久化会话/指标与逐资产上传队列，使用稳定来源会话、试次、资产及幂等 ID；断网或重启后可恢复。
- 会话、视频上传、媒体处理、报告生成分别记录状态；“部分完成”只是界面汇总，不是唯一事实字段。
- 会话建议状态为 LocalOnly、Submitting、Accepted、Failed；视频上传为 Pending、Uploading、Verifying、UploadedVerified、Failed；媒体处理为 NotRequested、Queued、Processing、Ready、Failed。枚举及迁移由接口评审冻结。
- 同幂等键同内容返回已有结果；同键不同内容报告冲突，不静默覆盖。重传一个视频不重建整个会话。
- 同机构内以 Hub SessionId、可空 TrialId、AssetId 关联文件；外部 ID 必须包含来源/安装作用域。服务端验证人员、试次及文件归属，不依赖文件名匹配。
- 会话 Accepted 后有效指标可读；视频未完成显示明确状态。若方案要求视频完整归档，另设完整性标记，不因此隐藏全部已接受指标。
- **验收：** API 已成功但 App 超时重试不重复；视频失败只恢复该资产；重启保留待上传任务；会话已接受但视频不可用时显示准确。

### FR-08 文件归档与视频上传（P0；会议方向＋用户确认＋产品补充）

- 接收约定的原始数据、App 报告 PDF/图片及视频。业务库保存类型、大小、可用校验值、来源、上传状态和会话/试次/资产关联，文件字节存私有对象存储。
- 会话数据上传与视频上传分开；API 负责授权和记录，App 逐资产直传对象存储，不能将视频字节放入 MQ 或要求通过普通业务 API 中转。
- 支持约定网络场景下的中断恢复与必要的分片/断点续传。凭证过期可重新授权，不能因此创建重复逻辑资产；具体上传模式须用实际视频样本验证。
- 客户端完成通知或存储事件仅触发核验，服务端验证对象存在、大小、完整性、租户及预期关联。分片上传的 ETag 不默认等同于整文件 MD5。
- 只有通过核验，才在本地事务内更新 UploadedVerified 并写入待处理事件。对象上传成功不等于视频已可播放。
- 上传、原片下载及播放的权限分别控制，不提供永久公开视频地址。短时凭证限制资源、操作及有效期，长期服务密钥不进入客户端。
- 视频是本产品一期支持能力，不代表每个测试必须附视频。某方案的必需/可选视频由模板明确；原片、播放版本及封面分别受保留/删除政策管理。
- **验收：** 核验失败不推进处理；完成通知重复/漏发可去重并核对；跨机构不能上传、关联或下载；上传中断不破坏会话指标。
- **待冻结：** 编码/格式、最大大小与时长、每测试数量、上传并发/速率、播放兼容范围、配额与保留期。支持视频不等于无限量存储。

### FR-09 历史、统计与图表（P0；会议明确＋补充）

- 按人员、分组、时间、测试协议和来源过滤；详情保留试次、单位和质量/缺失标记。
- 提供指标基础柱状图及明细表；折线图是否纳入按 D-04。
- 每项统计显示入选记录、样本数、时间范围、试次取值与汇总规则；无数据不当作 0。
- 一期只实现选定方案需要的统计口径。平均值、最大值等逐项明确，不能从“基础统计”推导出任意算法。
- 不兼容定义、不同方法或不可换算单位禁止直接合并；明确单位转换需保留原值并注明。
- **验收：** 固定样本的明细、图表与报告数值一致；过滤条件变化能追溯；被排除数据有原因；无跨机构聚合。

### FR-10 在线报告、视频播放与导出（P0；会议明确＋用户确认＋产品补充）

- 区分 App 上传的原报告、Hub 在线统计/方案报告及后续多产品综合报告；在线报告按会话/试次/资产引用展示视频。
- 在线报告显示已接受的指标，并逐视频显示待上传、处理中、可播放、失败。一个视频失败不影响其他有效指标或视频展示。
- Ready 视频经服务端再次校验机构成员、人员/报告/视频权限和有效媒资版本后获取短时播放凭证；播放器通过受控媒体分发取流，视频字节不经普通 API 主机。
- 一期基础播放器支持播放、暂停、进度定位和必要的错误/过期处理；浏览器、终端、格式及性能矩阵在试点前冻结。不默认承诺多机位同步、逐帧分析或标注。
- CDN 回源权限与观众鉴权分别配置；缓存命中仍须按策略鉴权。凭证到期需重新校验授权；撤回后停止新凭证，已有凭证和缓冲的失效边界按 §10 冻结，不承诺立即追回已下载副本。
- Hub 报告包含机构、人员编号、方案/模板版本、测试日期/来源、指标/单位、取值规则、缺项和生成时间；保存选数引用及必要快照。模板变化不静默重写旧报告。
- 必需指标缺失时阻止“完整报告”，允许明确标记的草稿；视频的完整归档要求单独定义，不混同于会话接收或报告文件生成。
- 导出建议 PDF＋CSV；是否必须 XLSX 由 D-05 冻结。PDF 可含视频标识、状态或经批准的访问入口，不承诺 PDF 文件内嵌视频播放，不写入长期有效的视频链接。
- 导出及后续下载均校验权限与脱敏；记录发起人、数据范围、模板版本和状态。
- **验收：** 在线报告指标与入选记录一致；视频能在指定兼容环境播放/暂停/定位；状态准确；跨机构、撤回或篡改媒资 ID 不获得新播放权；PDF 中文清晰且不输出诊断结论。

### FR-11 数据分级、同意与脱敏（P0；会议方向＋补充）

- 对字段及数据用途建立分级清单；人员身份、健康信息、运动测量数据按实际风险评审，不能仅因“指标”就默认无敏感性。
- 统计汇总经审查才可作为公开内容；不得把可重识别的小样本人群自动归为公开数据。
- 保存适用的同意/授权文本版本、主体、用途、范围、时间与状态；未获所需授权的操作被阻止。
- 展示、报表和科研导出采用不同脱敏规则；不必要的证件号、病史不作为默认必填项。
- **验收：** 普通角色看不到未授权敏感字段；导出不因界面已脱敏而漏出原值；授权范围外用途不可执行。

### FR-12 撤回、删除与审计（P0；会议方向＋补充）

- 授权撤回与数据删除分开：撤回停止相应授权使用，不自动等于立即删除所有记录。
- 提供受控删除申请、影响范围预览、执行记录与状态；覆盖派生报告、附件、缓存和来源映射的处理规则。
- 保留、备份到期清除、必要审计元数据及不能立即删除情形，由隐私/业务负责人审核；备份恢复后须重新应用删除清单。视频清理覆盖原片、媒资、播放版本、封面和适用 CDN 缓存；过期消息/回调不得复活已删除资产。
- 审计至少覆盖登录/失败、成员和角色变更、人员关联、敏感读取、下载/导出、撤回、删除和运维临时访问；日志不得记录令牌或完整敏感内容。
- **验收：** 撤回后的新请求被拒绝；删除任务有结果及失败处理；已删除对象不因缓存或恢复重新对用户可见；审计可按关联 ID 追踪。
- 系统不能追回已合法下载到外部的副本；界面和操作说明应准确表达撤回边界。

### FR-13 历史迁移与客户端切换（P0 规划；执行批次待决策）

- 建立 1.0 数据量、表/文件、人员规则、来源版本及数据质量清单，指定源系统负责人。
- 提供字段/指标/身份映射、重复冲突、缺失文件、未知单位和版本的处理规则；异常隔离，不伪造补齐。
- 迁移任务有批次 ID、可重复执行规则、失败清单和数量/校验核对。
- 区分历史回填与新数据接入；按客户端/机构计划最终增量、写入切换与回退，避免长期无规则双写。
- 生产客户切换时 App 与 Hub 协同发布；未完成相应客户端联调不得宣称客户已迁移。
- **验收：** 脱敏样本试迁移后人员、会话、指标和附件可对账；重复跑不制造重复记录；旧新差异有解释；回退路径经过演练或桌面验证。
- 会议要求分阶段考虑迁移，不等于一期展会前完成所有历史数据迁移。

### FR-14 展会闭环与易用性（P0；会议方向＋补充）

- 至少选定一套真实可执行方案，明确测试、指标、角色、设备、网络条件和报告样例。
- 在一期同一前端实现；大屏展示可复用报告页面，不增加 BI 大屏项目。
- 演示使用合成或经批准脱敏数据；如预置记录，明确“示例数据”，不伪装实时上传。
- 由代表用户完成“找人员—找测试—比较—导报告”任务，记录失败点并修复阻断问题。
- **验收：** 约定环境下完整演练，保留证据；断网有明确提示和预案，不出现假成功；展示语言按 D-08 确认。

### FR-15 可靠媒体任务与消息协调（P0 可靠性要求；技术方案评审后冻结）

- 采用技术架构 V0.3 的 MQ＋Outbox＋Worker 作为建议实现基线。数据库是业务事实源，MQ 只交付任务；App 本地队列、服务端 Outbox、MQ 和消费记录各有职责。
- 文件核验后，在同一数据库事务提交资产状态及 Outbox。Relay 只发布已提交事件，发送失败保留重试；发送成功但标记失败允许重复投递。
- 媒体处理与报告导出使用独立工作队列或等效资源隔离，控制并发、重试和积压，防止长视频拖垮普通报告。消息只携带 EventId、资源/租户引用、任务版本及关联 ID，不放视频、密钥或长期 URL。
- 消费端重新检查资产归属、上传核验状态、修订、删除标记及任务有效性，以唯一逻辑任务键、消费记录和条件更新防重；不能假设严格顺序或只投递一次。
- Worker 发起 VOD 媒资注册/转码并持久化 MediaId、任务 ID 和 Processing 后，可确认这次消息；确认不代表转码完成。不能占住消息等待长时间转码；短任务超时按配置续租/延长可见性。
- 外部调用已成功但本地记录丢失的模糊结果，应先查询/对账再重试，不能认为数据库去重自动保证外部副作用只发生一次。
- 回调按供应商支持方式验证真实性，并核实账号、任务、资产及处理版本；持久化更新后才确认接收。旧版本、乱序、重复和删除后的回调不得错误覆盖状态。
- 定期核对卡住的上传、Queued/Processing 任务和漏发回调；消息保留到期或任务丢失时，依据业务记录以同一逻辑任务重新投递。
- 暂时故障采用有限退避重试；永久错误或超预算进入持久化失败记录、告警及受控重放。清理孤立对象和执行补偿需有范围与审计。
- **验收：** MQ 暂不可用时会话正常接收、Outbox 可恢复；Relay/Worker 崩溃及重复投递不产生重复有效业务版本；回调缺失可补齐；媒体积压不阻塞基本查询。

## 7. 数据模型与科学可追溯性

以下为逻辑对象，复用现有实体并由技术设计确认物理表，不要求重复创建同义表。

| 对象 | 核心职责与约束 |
|---|---|
| Organization / User / Membership | 机构、账号与机构内角色；账号不等于运动员 |
| Subject / SourceIdentityMapping | 机构管理的标准人员与来源映射；同名不合并 |
| Team / Membership | 基础分组与成员关系 |
| TestProtocol / Version | 单项测试规则及版本 |
| AssessmentPlan / Version / Item | 组合方案及所需指标、来源约束与取值规则 |
| DataSource / Device | 应用来源与物理设备分离；保留版本和标识 |
| Session / Trial / SessionDevice | 测试事件、多试次及可能的多设备关联；不强制一期多设备采集 |
| MetricDefinition / Result | 指标定义与结果分离；代码、方法、单位、版本及类型明确 |
| DataObject / MediaAsset | 原始文件、App 报告、视频及 Hub 报告；媒体字段可扩展现有对象，不强制重复建表 |
| MediaProcessingTask / MediaRevision | 媒体任务、资产修订、处理配置、供应商媒资/任务 ID 及状态；不等于科学计算任务 |
| OutboxEvent / ConsumptionRecord | 同库待发事件、投递进度、消费去重及恢复记录 |
| Report / ReportSnapshot | 引用方案/模板与选定数据，支持追溯和受控删除 |
| SyncOperation | 幂等、提交指纹、状态、错误及来源追踪 |
| Consent / Authorization / AuditEvent | 用途授权、变更历史与操作审计 |
| MigrationBatch / Mapping | 老库来源、迁移状态和核对结果 |

关键规则：

1. 人员、会话、试次、附件、报告保持明确关联；所有访问可回溯到租户。
2. 时间以 UTC 保存，保留来源时区/偏移；界面与报告标注展示时区。
3. 标量、双侧值、分类及结构化结果按首个 App 实际输出支持，不把所有结果塞入单一数字字段。
4. App 指标同时保留提交原值、原单位、来源与可用版本；展示换算不能静默改写原数据。
5. 会话协议版本、指标定义版本、App 算法版本、方案版本和报告模板版本分别管理。
6. 组合方案可引用同一人员多个会话；不得为生成综合报告强行把所有测试改成同一次 Session。
7. 一期无 `ProcessingJob` 科学计算强制依赖。文件校验、媒体处理、导出与科学计算任务分开命名；不要因加入 Worker 而恢复云端科学算法范围。
8. 业务记录保存 AssetId、可空 TrialId、可验证的机构/人员关联及媒资修订；报告不能只保存一个无法授权追溯的裸视频 URL。
9. EventId 与逻辑处理键分别管理；修订/转码配置变化创建新处理版本，同任务重试不创建新逻辑任务。

## 8. 接口与集成要求

### 8.1 一期内部 API 能力组

认证及机构上下文、人员/分组、协议/方案读取、会话/试次/指标上传与查询、逐资产上传授权与完成确认/下载、同步状态、媒体处理状态、报告生成/查询、视频播放授权及导出。供应商回调入口与内部任务接口不作为普通客户端写入业务状态的后门。

接口路径、DTO 和数据库命名以现有仓库审查及双方契约为准；本文不将示例路径当成已实现接口。

### 8.2 契约冻结输入

- 每类测试至少一份真实脱敏的成功 payload、边界 payload 与附件样本。
- 字段类型、必填性、单位、允许范围、协议/指标版本和外部 ID 作用域。
- 幂等、更新/更正、重试、部分接收和冲突处理规则。
- 批量大小、最大文件、超时、速率及 API 兼容窗口。
- 认证授权方式；原生客户端不得嵌入长期保密服务密钥。
- 客户端/服务端相关 ID 与稳定错误码；给操作员可理解提示。
- 会话与资产关联、视频直传/分片/续传、完成核验、消息幂等键、媒体修订、回调验证/去重和状态对账。
- 播放凭证签发、过期续取、撤回生效及兼容矩阵；短时凭证不得代替资源权限检查。

### 8.3 对外开放边界

面向 App/Web 的服务 API 是一期必要能力。第三方开发者注册、API 调用包、公开 SDK、Webhook、门户和计费是另一组产品需求；由研发评估后排期，不从“开放 API”一句话推导为一期全部交付。

| 运维 | 接入失败率、失败队列、文件容量、延迟、导出失败与权限异常可观测 | 告警触发与问题定位演练 |

### 9.1 技术职责与采用边界

| 概念 | 一期方案 |
|---|---|
| 云与容器 | 阿里云已确认；建议新 ECS 承载 Web/API/Worker 容器，ACK 不是必要前置；地域、数量及规格未定 |
| 模块化单体 / DDD | 按机构、人员、测试、方案报告及媒体规则划分模块；轻量 DDD 不要求微服务、完整 CQRS 或 Event Sourcing |
| MQ / Outbox / Worker | 依据 FR-15 做可靠投递与受控处理；SMQ（原 MNS）为优先评估产品，具体地域、SDK、重试和失败队列须联调 |
| 数据与文件 | 建议 RDS PostgreSQL 保存业务状态、私有 OSS 存原片和报告；不把大视频存数据库或 ECS 系统盘 |
| 视频服务 | 建议 VOD 做媒资/转码，CDN 分发；支持的自有 OSS 注册配置先验证，否则评估受控导入及重复存储成本 |
| 并发 | API 异步 I/O、数据库连接池、Worker 有界并发；不为每在线用户创建线程，不无限 Task.Run |
| 一致性 | 同数据库用本地事务；外部 OSS/VOD 用持久化流程、幂等、重试及对账，不把云端调用包进长数据库事务 |
| 扩展 | 业务 API 无状态，可按压测水平扩容；MQ、Worker 独立不等于全面微服务化；Redis 等额外组件按实测需要评审 |

MQ 的目标是可靠解耦与削峰，并非要求所有 API 经过 MQ。科学计算仍留 App；视频转码为媒体处理。多个容器共用一台 ECS 不构成主机故障隔离；高可用拓扑需结合 RPO/RTO 与预算评审。

### 9.2 可观测性及文件治理

至少监控 API 延迟/错误、数据库连接与慢查询、Outbox 最老待发时间、队列积压和任务年龄、重投/失败、Worker 资源、上传失败、转码延迟、播放错误及视频流量。消息/日志不记录访问密钥、完整敏感字段或可用长期链接；关联 ID 支持从会话追踪到资产、事件与媒体任务。备份与恢复覆盖业务记录及对象文件，CDN 缓存和转码副本不能替代备份。

| AC-04 | App 重启/断网/附件失败后恢复 | 待同步任务保留，可重试失败部分，无假成功 |
| AC-05 | 用户篡改其他机构资源 ID | 列表、详情、写入、导出及文件访问均不能越权 |
| AC-06 | 角色降权或撤回授权 | 在规定时效内后续访问失效；审计可追踪 |
| AC-07 | 比较不同单位/定义或缺失指标 | 不静默混算；缺失不为零；统计与明细一致 |
| AC-08 | 方案选取多个会话与版本 | 全部属于同一授权人员/机构；取值规则和缺项明确 |
| AC-09 | 模板更新后查看旧报告 | 原报告及其引用/快照可追溯；无静默改写 |
| AC-10 | 中文 PDF 与结构化导出 | 无截断乱码；数值单位正确；权限与脱敏生效 |
| AC-11 | 未部署科学 worker | App 已计算结果仍可完整上传、比较和出报告 |
| AC-12 | 历史样本试迁移及重复运行 | 映射、数量、文件校验可核对，无重复与无解释丢失 |
| AC-13 | 备份恢复与删除清单重放 | 满足已冻结 RPO/RTO；已删除内容不重新对用户可见 |
| AC-14 | 展会流程与网络故障 | 约定方案可演练；真实与示例清楚区分，故障有反馈 |
| AC-15 | 会话已接受但视频待上传/失败 | 指标可查看，视频显示实际状态；不重建会话 |
| AC-16 | 视频中断、凭证过期或 App 重启 | 逐资产恢复/重新授权，不重复或错误关联 |
| AC-17 | 完成通知重复、漏发或文件不完整 | 核验后才投递；可补齐遗漏，不生成重复资产/事件 |
| AC-18 | MQ 不可用或 Relay 在发送后崩溃 | Outbox 保留并恢复；允许重复投递，业务无重复有效版本 |
| AC-19 | Worker 崩溃、消息重投或处理超时 | 消费幂等、任务可恢复，有限重试/失败处理有效 |
| AC-20 | VOD 提交成功但本地超时 | 查询/对账后处理模糊结果，不盲目创建重复媒资 |
| AC-21 | 回调漏发、乱序、旧版本或删除后回调 | 主动查询补齐，旧状态不覆盖新状态，删除资产不复活 |
| AC-22 | 报告中播放、暂停、定位及凭证过期 | 指定兼容环境正常播放，过期后重新授权；PDF 不冒充播放器 |
| AC-23 | 跨机构媒资、撤回或删除后播放 | 不签发新越权凭证；链接/缓存按已冻结时效和清理策略处理 |
| AC-24 | 规定负载下 API、视频及后台任务并发 | 分别满足冻结指标，媒体积压不无限占用资源或阻断基本查询 |

**演示门槛：** 选定方案完整演练，数据来源标注清晰；使用真实个人数据时仍须具备适用的隔离与授权能力。  
**试点门槛：** 所有已冻结 P0 用例通过（含 AC-15～24 媒体及消息用例），量化目标达标，无阻断流程、数据丢失或越权缺陷，备份恢复完成。  
**商业上线门槛：** 在试点基础上完成适用的迁移切换、客户发布、生产容量、支持与数据治理评审。演示完成不自动等于可正式商用。
