### Implementation rules

## 2. Introduce semantic color tokens

The current Tailwind configurations use literal color values for palettes such as `ink`, `kunwei`, and `teal`. Simply adding a `light` class to the root will not change those existing hard-coded utility colors.

Instead, introduce a layer of semantic CSS variables. Components should reference the role of a color—such as `--surface-sidebar` or `--text-primary`—rather than assuming a particular color palette.

## 3. Add a small theme provider or hook to each app

Because the two apps are separate React applications, each should own its theme state and storage key. The code can follow the same contract without needing to share runtime state across apps.

A small reusable hook is sufficient if each app only has one top-level layout. If either app already has a global provider pattern, integrate theme state there rather than creating a competing provider.

```
import { useEffect, useState } from "react";

export type AppTheme = "classic" | "light";

const STORAGE_KEY = "kwinhub.web-react.theme";
// Use "kwinhub.platform-console.theme" in PlatformConsole.

function readSavedTheme(): AppTheme {
  try {
    const value = window.localStorage.getItem(STORAGE_KEY);
    return value === "light" || value === "classic"
      ? value
      : "classic";
  } catch {
    return "classic";
  }
}

export function useAppTheme() {
  const [theme, setTheme] = useState<AppTheme>(readSavedTheme);

  useEffect(() => {
    document.documentElement.dataset.theme = theme;

    try {
      window.localStorage.setItem(STORAGE_KEY, theme);
    } catch {
      // Keep theme switching usable when storage is unavailable.
    }
  }, [theme]);

  return { theme, setTheme };
}
```

Implementation details to preserve:

- Use a unique key per app, as shown above.
- Keep the stored values limited to `classic` and `light`; don't store CSS colors or entire theme objects.
- If server-side rendering is introduced later, guard browser API access and avoid reading `window` during server rendering.
- To reduce a flash of the wrong theme on page load, initialize `data-theme` from the saved preference before the React application paints, using the app's existing HTML entry point if practical. Keep that initialization script small and consistent with the same storage key and fallback.
- If the app's existing architecture already has a theme provider, prefer extending it instead of introducing duplicate state.
